# A11y handoff integration review

Source: [uxpraveenkumar-dotcom/desigma, review/a11y-handoff](https://github.com/uxpraveenkumar-dotcom/desigma/tree/ba3961dd1aab5751432854d31798dc3a107c9886).
Destination baseline: A11y `415703caad0e846bcac8a66796b61f1832cdfbbe`.
Common ancestor: `37a8559`.

## Integrated functionality

- Document tabs with saved viewport/selection, tab previews, and navigation history.
- Local organizations with separate project directories, an organization selector, project cards, folder creation, and editable display names.
- Clipboard images, files, plain text and SVG; paste at the pointer; cross-document layer copying.
- Inline frame renaming, comment visibility toggle, contextual actions, immediate text Hug sizing, and Alt-hover measurements.
- Opt-in AI image generation/editing through the user's OpenRouter account, brush masks, image history, and OS credential storage.
- MCP component creation/instances, instance overrides and sync/detach, and page renaming; document-memory diagnostic example and agent workflow documentation.
- Organization/team/resource permission policy and snapshot storage, with unit tests.

The desktop additions are enabled by the default `enhanced-desktop` feature. No separate “Design App” identity or data directory is introduced.

## Review findings and integration fixes

1. **Shared workspace name collision and persistence risk.** The incoming local-organization modules used the same module/field names as A11y's server-backed shared library. They are integrated as `organizations`; `workspace` remains the shared library. Organization switching and restart retain the base library's shared-server connection and cached file list.
2. **Existing functionality removed upstream.** The handoff deleted the MCP/Claude connection screen, hid New board in the enhanced home, and replaced frame menus with a smaller list lacking developer-status actions. These existing capabilities are preserved alongside the additions.
3. **Late AI result could alter another document.** Switching documents or returning home now cancels pending result application. The document's read-only state is checked again before a result is applied.
4. **Generated-image undo was two operations.** The incoming test required two Undo actions despite its name. Placement, centering and initial AI history are now one transaction; the test requires one Undo.
5. **Organization lifecycle and old agent context.** Changing organizations first returns home through the existing save/leave safeguards. It revokes the old plugin session and MCP bridge and reloads organization settings. An agent cannot remain attached to the previous organization while editing the new one.
6. **Renamed deep-link prefix length.** The incoming `desigma://open` logic used numeric string offsets. The A11y integration uses the actual `a11y://open` prefix length, retaining existing legacy join-link support.
7. **Identity and updates.** A11y branding, package names, icons, legacy library discovery, existing file formats, shared server API/transport, and the disabled automatic updater remain intact. The handoff's standalone macOS packaging is not used.

## Scope and rollout limits

Local organizations organize files on one computer. They are not synchronized server organizations or access boundaries for the shared library. The imported permission model is not connected to authenticated server accounts, HTTP authorization, or collaboration admission. The existing workspace key still grants workspace-wide access; no new enforcement is claimed.

AI generation sends prompts and selected reference images only after the user invokes generation. It requires the user's configured provider key/model; no paid provider requests were made during integration testing. The API contract was checked against [OpenRouter's image API documentation](https://openrouter.ai/docs/api/api-reference/images/list-image-models); automated generation tests use a local fake server.

Use matching updated clients and library server when deploying these features. Older binaries can ignore the new optional AI-history metadata when saving; retaining old executables is not a test of new metadata persistence. Existing running apps, user files, live server data and distributed ZIPs were not replaced during this source integration.

## Validation

- Workspace/all-target build check, strict Clippy (`-D warnings`), and Rustfmt: passed.
- App: 1,040 passed; two existing ignored tests; two live-network cases filtered. This includes synthetic UI, local HTTP AI fixtures, simulated collaboration, shared-connection persistence, and tab save-failure safeguards.
- AI subset after the single-undo fix: 13 passed.
- Document, engine and library: 264 + 41 + 31 passed (336 total).
- MCP library, session and stdio: 11 + 13 + 9 passed (33 total).
- Server library and shared-library-server unit tests: 5 + 1 passed.
- Windows x64 release build (editor and both helper tools): passed. Executable launch on Windows has not been tested here.
- Live-network checks were attempted: six server integration tests cannot start the macOS network monitor (`Failed to create netmon monitor`); two app tests time out waiting for that host. The same environment restriction affected earlier A11y testing. These are not counted as passes. All 34 simulated collaboration tests pass. The server and transport implementation files are unchanged by this integration.

Run `scripts/verify-handoff.sh --live` on an unrestricted development machine with Rust 1.93.1. Before replacing the deployed test server, confirm with two updated clients that a collaborator can keep editing after the creator disconnects, that changes survive a server restart, and that the creator sees those changes on return. Also check native clipboard interactions and tab navigation on macOS and Windows.

Native Windows launching and a human review of the macOS UI remain acceptance checks beyond compilation and synthetic UI tests.
